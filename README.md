# C 板框架大作业

## 概述

大作业基于C板进行，并且自然地承接到后续小车控制的任务。我们希望通过这个作业让大家温习前面学过的所有知识，建立自己的嵌入式架构和知识体系，并为后续的嵌入式开发做好准备。请仔细阅读本文档以明确所有任务。

### 项目结构

| 路径 | 用途 |
| --- | --- |
| [`board/board.ioc`](board/board.ioc) | STM32CubeMX 外设配置入口；生成的板级代码与 CMake 工程也在 `board/` 下 |
| [`bsp/`](bsp/) | CAN、UART、PWM 等外设封装；SPI、I²C 需要自行补充 |
| [`libs/`](libs/) | PID、数值工具和 CRC |
| [`modules/`](modules/) | BMI088、DJI 电机及 M2006 模块 |
| [`threads/`](threads/) | 自行设计并实现的 ThreadX 线程 |
| [`docs/`](docs/) | 推导、学习记录和调试日志 |

框架保留了多处 `TODO`。这些接口在完成前只是练习骨架，不能视为可直接驱动硬件的实现。先完成 CubeMX 配置并生成所需头文件，再在 `board/CMakeLists.txt` 中启用 C++，加入 `bsp/`、`libs/`、`modules/` 的源文件和头文件路径，逐项编译与调试。`board/` 是板级 CMake 工程入口。

### 执行步骤
1. Fork 或克隆仓库，并复制到你自己的仓库。
2. 从 [`board/board.ioc`](board/board.ioc) 开始配置时钟、GPIO、UART、PWM、CAN、SPI 和 I²C，重新生成板级代码；不要直接复制以前的板级配置。
3. 了解作业：学习与文档部分以 [`docs/chassis.md`](docs/chassis.md) 为必做记录，[`docs/ahrs.md`](docs/ahrs.md) 为选做记录。开发部分需要补全框架，并实现 BMI088 数据读取和单电机控制。
4. 思考如何和agent合作，将你的需求、理解、要求和agent进行交互并形成一个良好的项目规范、项目要求与执行计划，实现你的[AGENTS.md](AGENTS.md) 并在开发过程中不断改进、完善，鼓励大家在独立思考的同时和agent进行有规划的交互。你应该选择一个可靠的agent。
5. 按 `bsp → libs → modules → threads` 的依赖顺序编写与调试。为各功能设置开关，或通过线程是否启动进行区分；一次只验证少量功能，记录现象与修改。

### 过程要求
这个作业对大家可能提出了比较高的要求，但是我们希望大家能通过努力从中真正学到开发要用的东西。
1. 如果你对C++/C，函数，类与对象还不熟悉，请你先进行自学。
2. 如果你对之前的配置、调试、编写还不熟悉，也请先复习熟悉。
3. 尽量独立思考、搜索、寻找答案，可以适当地提问，但是手把手的教学和解答将不再存在。
4. 鼓励通过文档 [logs](docs/logs.md) 记录自己的调试过程、迭代过程，为后续开发打好基础。
5. 推荐大家主动搜索一些参考资料，如果认为资料非常有用，希望大家可以分享给其它人，你可以将你搜索和学习的路径放到 [references](docs/refereces.md)

### 提交规范
1. 只有必要的agent产物被保留
2. 尽量完全遵循原有的结构设计与文档设计，保持项目的简洁
3. 文档、代码尽可能简洁并体现你的思考，而不是用agent写出来很长很冗余的产物
4. 保持你 git commit 的良好习惯，写清楚每一次commit做了什么
5. 提交你的 repository 链接

## 学习-文档作业

### 底盘解算

搜索资料并掌握麦克纳姆轮、全向轮、舵轮的底盘解算
- 理解麦克纳姆轮、全向轮是如何通过辊子的排布实现全向移动的，并通过计算和推导理解如何将 $v_x,v_y,v_w$ 解算为四个轮子的线速度
- 理解舵轮是如何通过舵向电机和舵轮电机的配合实现全向移动的，并通过计算和推导理解如何将 $v_x,v_y,v_w$ 解算为舵向电机的角度和舵轮电机的速度

将解算和推导过程写下来，你可以使用md，可以手写上传图片，希望你能有一个良好的思考过程，如果能将过程和理解写下来就更好了。请将你的结果写到 [chassis](docs/chassis.md)

完成上面的部分之后，学习-文档作业的基础内容就已经完结，后续内容为选做。

### 功率计算

搜索资料并尝试了解

- 如何通过采样确定电机功率公式的常数，使用了什么方法，需要采集什么数据
- 不同轮组分别在什么场景下具有优势，半舵半全向这种构型为什么会存在

如果你有所发现，请添加到 [chassis](docs/chassis.md)

这部分需要的数学知识比较多，但是理解过后对于机器人的姿态、运动都会有更深入的了解。

- 矩阵、旋转矩阵分别是什么？如何从简单的二维旋转推广到三维旋转？

## 开发作业

这部分内容为必做。

### 前置知识

了解这部分知识能够补全通信知识，帮你建立完整的通信知识体系。

搜索资料并了解
- 全双工、半双工通信分别指的是什么？
- 什么是SPI？SPI通信具有什么特点？
- 什么是 I²C？I²C 通信具有什么特点？

将你的学习、配置过程记录到 [spi](docs/spi.md), [iic](docs/iic.md)

### 配置

配置清单：

- 时钟树，注意主频
- GPIO，三种颜色的灯都需要配置
- PWM，控制舵机的那个口
- UART，把两个串口都打开
- CAN，打开并配置所有CAN
- SPI，根据数据手册进行配置
- I²C，根据数据手册进行配置
- Thread，优先级，栈空间，内存分配
- 整体的堆栈空间

完成配置时注意生成 `board/CMakeLists.txt`，同时建议在 CubeMX 中勾选 `.c/.h pair`。

### bsp

- 补全 CAN、UART、PWM 封装。检查句柄、数据长度、中断与 DMA 配置，避免在未初始化时发送数据。
- 外设 HAL 调用集中在 BSP；LED 模块可直接封装 HAL GPIO; IMU模块可直接调用 HAL SPI 和 HAL GPIO

### libs

补全 PID 的位置式与增量式计算，检查输出和积分限幅；保留的 CRC 与基础数值函数可用于通信和控制。

### modules

- 完成 BMI088 的 SPI 读写、GPIO 片选、芯片 ID 校验、配置，以及加速度、角速度和温度解析；按数据手册确认量程、单位与加速度计读取时需要丢弃的无效字节。
- 完成 M2006 的速度环、位置与速度双环控制，以及电机注册、CAN 报文打包和反馈解析。
- 自行实现 LED 模块。GPIO/SPI 的实际连接和 PID 参数应根据自己生成的板级配置填写。
- 选做：实现IST8310的读取

### threads

你需要设计并完成下面的threads，并合理地创建与启用，你可以在基础功能之上自由发挥，实现你的小巧思。记得sleep。
- alive : 使用信号量`tx_semaphore_put`和`tx_semaphore_get`完成对板子不同进程的监控，并通过灯效反映。主要监控：初始化是否成功，BMI088线程是否存活，电机控制线程是否存活
- imu : 完成 BMI088 初始化，读取加速度、角速度和温度并提供给其他线程
- imu选做 : 通过IST8310读取磁力计
- imu选做 : 实现6轴甚至9轴的IMU解算，并思考我们为什么在场上不使用9轴IMU解算
- control : 完成简单的单电机双环PID控制

### 完成检查

- `board/` 工程能编译、下载，且各外设单独验证通过。
- BMI088 芯片 ID 正确，三轴数据和温度单位明确；通信失败时能识别错误。
- 单电机在松开模式下输出为零，速度环与双环控制分别验证，CAN 报文的 ID 和字节顺序正确。
- 线程按需启用，含适当的休眠或同步；调试过程记录在 [`docs/logs.md`](docs/logs.md)。
